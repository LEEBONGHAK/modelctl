# PR #26 — Add compatibility remediation plans

- Pull request: https://github.com/LEEBONGHAK/modelctl/pull/26
- Status: Open (draft)
- Base / head: `refac` ← `feat/compatibility-remediation-plan`

## English

### Context

PR #25 introduced capability-driven launcher decisions and immutable launch requests. Compatibility warnings could identify a mismatch, but users still had to interpret the warning and change the launcher manually. The next increment needs to show the exact proposed change before mutating configuration.

### Changes

- Added an immutable `CompatibilityRemediation` result containing the current launcher, warning, recommendation, installation state, and whether a change is required.
- Added `modelctl launchers remediate` as a read-only compatibility plan.
- Added `modelctl launchers remediate --apply` as an explicit configuration change.
- Refused apply when the recommended launcher is unavailable on `PATH`.
- Returned a successful no-op plan when the active launcher has no known mismatch.
- Reused launcher capabilities for translated-provider and native-provider recommendations.
- Updated compatibility warnings to point to preview and apply commands instead of a hard-coded launcher ID.
- Added service and CLI regression tests for preview, apply, no-op, unavailable, and unsupported remediation paths.
- Updated English and Korean usage, changelog, project progress, and PR engineering history.

### Safety and scope

Preview never changes configuration. Apply changes only the selected launcher and does not install software, change the provider or model, or execute a launcher. Broader remediation actions remain deferred until they have a proven safe and reversible workflow.

### Validation and outcome

The pull request remains draft until dependency audit, Ruff, complete Ubuntu/macOS/Windows tests, package builds, installed-wheel smoke tests, and release dry-run all pass.

## 한국어

### 배경

PR #25에서 capability 기반 launcher 판단과 불변 launch request를 도입했습니다. 호환성 경고로 불일치를 확인할 수는 있었지만 사용자가 경고를 해석하고 launcher를 직접 변경해야 했습니다. 다음 기능은 설정을 변경하기 전에 정확한 변경 계획을 보여줘야 합니다.

### 변경 내용

- 현재 launcher, 경고, 권장 launcher, 설치 상태, 변경 필요 여부를 담는 불변 `CompatibilityRemediation` 결과를 추가했습니다.
- 읽기 전용 호환성 계획인 `modelctl launchers remediate`를 추가했습니다.
- 명시적으로 설정을 변경하는 `modelctl launchers remediate --apply`를 추가했습니다.
- 권장 launcher가 `PATH`에 없으면 적용을 거부합니다.
- Active launcher에 알려진 불일치가 없으면 성공적인 no-op 계획을 반환합니다.
- Provider 변환과 native provider 추천에 기존 launcher capability를 재사용합니다.
- 호환성 경고가 특정 launcher ID 대신 미리보기·적용 명령을 안내하도록 변경했습니다.
- 미리보기, 적용, no-op, 미설치, 지원되지 않는 remediation 경로를 service·CLI 회귀 테스트로 검증합니다.
- 영문·한국어 사용법, changelog, 프로젝트 진행 문서, PR 개발 이력을 갱신했습니다.

### 안전성과 범위

미리보기는 설정을 변경하지 않습니다. 적용은 선택된 launcher만 변경하며 소프트웨어 설치, provider·model 변경, launcher 실행을 수행하지 않습니다. 더 넓은 remediation 동작은 안전하고 되돌릴 수 있는 사용자 흐름이 검증된 뒤로 미룹니다.

### 검증 및 결과

Dependency audit, Ruff, Ubuntu·macOS·Windows 전체 테스트, package build, 설치된 wheel smoke test, release dry-run이 모두 통과할 때까지 draft로 유지합니다.

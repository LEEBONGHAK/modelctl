## English

### Context

With Claude Code and Gemini CLI supported, the project needed another launcher integration to continue validating the shared execution pattern before introducing richer capability abstractions.

### Changes

- Added and registered the Codex CLI launcher.
- Constructed commands as `codex --model <model> <args...>`.
- Added actionable installation guidance when Codex CLI is unavailable.
- Added command-construction and launcher-registry tests.
- Documented launcher selection and native argument forwarding.

### Validation and outcome

Users could configure and run Codex while forwarding its native options:

```bash
modelctl config set launcher codex
modelctl run --sandbox workspace-write
```

The PR confirmed that the small launcher contract could support multiple independent coding-agent CLIs.

## 한국어

### 배경

Claude Code와 Gemini CLI 지원 이후, 복잡한 capability 추상화를 도입하기 전에 공통 실행 패턴이 다른 launcher에도 적용되는지 계속 검증할 필요가 있었습니다.

### 변경 내용

- Codex CLI launcher를 추가하고 registry에 등록했습니다.
- 명령을 `codex --model <model> <args...>` 형식으로 구성했습니다.
- Codex CLI가 없을 때 실행 가능한 설치 안내를 추가했습니다.
- 명령 생성과 launcher registry 테스트를 추가했습니다.
- launcher 선택 및 네이티브 인자 전달 방법을 문서화했습니다.

### 검증 및 결과

다음처럼 Codex를 설정하고 고유 옵션을 전달할 수 있게 됐습니다.

```bash
modelctl config set launcher codex
modelctl run --sandbox workspace-write
```

작은 launcher 계약만으로도 서로 다른 코딩 에이전트 CLI를 지원할 수 있음을 확인했습니다.

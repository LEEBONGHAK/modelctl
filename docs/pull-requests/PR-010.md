## English

### Context

Native coding-agent CLIs are designed around their own providers. Passing an OpenRouter-selected model directly to Claude Code, Gemini CLI, or Codex CLI might work with an external proxy, but it could also fail without explanation.

### Changes

- Added native-provider metadata to Claude Code, Gemini CLI, and Codex CLI launchers.
- Added non-blocking mismatch warnings before execution.
- Reused the same compatibility rule in `modelctl doctor`.
- Continued forwarding model names unchanged for advanced proxy and custom-endpoint setups.
- Kept Aider as the automatic OpenRouter integration.
- Added launcher, runtime-service, and diagnostic tests.

### Validation and outcome

Potentially incompatible selections now produce actionable feedback without blocking advanced configurations. Strict policy enforcement and automatic remediation remained deferred.

## 한국어

### 배경

각 네이티브 코딩 에이전트 CLI는 자체 provider를 중심으로 설계됩니다. OpenRouter에서 선택한 모델을 Claude Code, Gemini CLI, Codex CLI에 그대로 전달하면 외부 프록시 환경에서는 동작할 수 있지만, 일반 환경에서는 이유를 알기 어려운 실패가 발생할 수 있었습니다.

### 변경 내용

- Claude Code, Gemini CLI, Codex CLI launcher에 native provider 메타데이터를 추가했습니다.
- 실행 전에 차단하지 않는 불일치 경고를 추가했습니다.
- 같은 호환성 규칙을 `modelctl doctor`에서도 사용했습니다.
- 고급 프록시·사용자 정의 endpoint 구성을 위해 모델 이름은 그대로 전달했습니다.
- Aider를 OpenRouter 자동 연동 launcher로 유지했습니다.
- launcher, runtime service, 진단 테스트를 추가했습니다.

### 검증 및 결과

잠재적으로 호환되지 않는 조합에 조치 가능한 안내를 제공하면서도 고급 구성을 강제로 차단하지 않게 됐습니다. 엄격한 정책과 자동 수정은 이후 작업으로 남겼습니다.

## English

### Context

Version `0.1.0` had passed its functional, security, cross-platform, packaging, and release-readiness gates. The user requested that a completed version be merged into `main`, while ongoing development should continue separately on `refac`.

### Changes

- Made `main` the canonical completed-version and release branch.
- Kept `refac` as the ongoing development branch.
- Changed release ancestry and publication checks from `refac` to `main`.
- Required trusted direct pushes or actually merged pull requests targeting `main`.
- Updated workflow regression tests for the `main` trust boundary.
- Aligned English and Korean README, progress, release criteria, release guide, and changelog.
- Preserved read-only pull-request dry runs, immutable tags and releases, and disabled PyPI publication.

### Validation and outcome

CI, Release dry run, Package, and the complete Ubuntu, macOS, and Windows test matrix passed. PR #19 was squash merged into `main` at commit `2cbde7f9ad9b8c2ce159850d72c0c51881fd68f1`. GitHub App connector merges did not emit the expected post-merge Actions event, so the following pull request introduced an owner-only, fully validated comment command to publish the tag and GitHub Release without weakening the release gates.

## English

### Context

Version 0.1.0 warns about mismatched provider and launcher selections but leaves remediation entirely manual. The first v0.2.0 feature turns that feedback into an explicit, inspectable recommendation without silently changing user configuration.

### Changes

- Added `modelctl launchers recommend` for provider-aware launcher inspection.
- Recommended Aider for OpenRouter and the matching native launcher for supported native providers.
- Added `--apply` as an explicit opt-in that refuses unavailable launchers.
- Returned the post-apply active state accurately and distinguished changed from already-active recommendations.
- Preserved existing launcher execution when older configuration has no provider context.
- Coordinated all package versions at `0.2.0` and set release status to `draft` so development cannot publish prematurely.
- Added a narrowly scoped temporary audit exception for `GHSA-g6cj-pr64-35w5`, documented in the security policy and tracked by issue #22 until `cryptography 50.0.0` is published.
- Updated English and Korean usage, progress, release, changelog, security, and PR-history documentation.
- Added service and CLI regression coverage for recommendation, application, unavailable launchers, unknown providers, state reporting, and backward-compatible execution.

### Validation and outcome

Dependency audit with the documented single-advisory exception, Ruff, the complete pytest suite on Ubuntu, macOS, and Windows, package builds, installed-wheel smoke tests, release validation, and checksum generation all passed before merge. PyPI publication remained disabled and no v0.2.0 tag was created.

## 한국어

### 배경

0.1.0은 provider와 launcher 선택이 맞지 않을 때 경고하지만 조치는 전적으로 수동이었습니다. v0.2.0의 첫 기능은 사용자 설정을 몰래 변경하지 않으면서 이 안내를 명시적으로 확인하고 적용할 수 있는 추천으로 발전시킵니다.

### 변경 내용

- Provider-aware 추천을 확인하는 `modelctl launchers recommend`를 추가했습니다.
- OpenRouter에는 Aider를, 지원되는 native provider에는 해당 native launcher를 추천합니다.
- 사용할 수 없는 launcher를 거부하는 명시적 opt-in `--apply`를 추가했습니다.
- 적용 후 active 상태를 정확히 반환하고 실제 변경과 이미 active인 상태를 구분했습니다.
- Provider context가 없는 기존 설정에서도 launcher 실행이 계속 동작하도록 호환성을 유지했습니다.
- 모든 package version을 `0.2.0`으로 맞추고 release status를 `draft`로 변경하여 개발 중 조기 게시를 차단했습니다.
- `cryptography 50.0.0` 배포 전까지 `GHSA-g6cj-pr64-35w5` 하나만 대상으로 하는 임시 audit 예외를 보안 정책에 기록하고 issue #22로 제거를 추적했습니다.
- 영문·한국어 사용법, 진행, 릴리스, changelog, 보안, PR 이력 문서를 갱신했습니다.
- 추천, 적용, 미설치 launcher, 알 수 없는 provider, 상태 표시, 하위 호환 실행을 service·CLI 회귀 테스트로 검증했습니다.

### 검증 및 결과

문서화된 단일 권고 예외를 적용한 dependency audit, Ruff, Ubuntu·macOS·Windows 전체 pytest, package build, 설치된 wheel smoke test, release 검증, checksum 생성이 병합 전에 모두 통과했습니다. PyPI 게시는 계속 비활성화되었고 v0.2.0 tag는 생성하지 않았습니다.

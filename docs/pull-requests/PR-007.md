## English

### Context

Multiple launchers were available, but users still had to know configuration keys and launcher IDs. A discoverable CLI workflow was needed before adding more integrations.

### Changes

- Added `modelctl launchers list` with a Rich table.
- Displayed launcher ID, name, active state, and local installation state.
- Added `modelctl launchers use <launcher-id>`.
- Validated unknown launcher IDs and displayed available choices.
- Exposed a shared cached launcher registry from the application container.
- Added CLI tests for listing, selection, persistence, and invalid values.
- Updated the quick-start workflow.

### Validation and outcome

Launcher management became discoverable and persistent:

```bash
modelctl launchers list
modelctl launchers use aider
```

The feature remained focused on the working CLI and deferred plugin discovery and capability refactoring.

## 한국어

### 배경

여러 launcher가 추가됐지만 사용자가 설정 키와 launcher ID를 직접 알고 있어야 했습니다. 연동을 더 확장하기 전에 지원 대상과 설치 상태를 확인하고 선택할 수 있는 CLI 흐름이 필요했습니다.

### 변경 내용

- Rich Table 기반 `modelctl launchers list`를 추가했습니다.
- launcher ID, 이름, 활성 상태, 로컬 설치 상태를 표시했습니다.
- `modelctl launchers use <launcher-id>`를 추가했습니다.
- 알 수 없는 ID를 검증하고 선택 가능한 목록을 안내했습니다.
- 애플리케이션 컨테이너에서 공유·캐시되는 launcher registry를 노출했습니다.
- 목록, 선택, 저장, 잘못된 값에 대한 CLI 테스트를 추가했습니다.
- Quick start 흐름을 갱신했습니다.

### 검증 및 결과

다음처럼 launcher를 탐색하고 영속적으로 선택할 수 있게 됐습니다.

```bash
modelctl launchers list
modelctl launchers use aider
```

기능 범위는 실제 CLI 사용성에 집중하고 plugin discovery와 capability 리팩터링은 연기했습니다.

## English

### Context

The first three v0.2.0 increments proved concrete runtime requirements: provider-aware recommendations, OpenRouter model translation, native argument forwarding, and persisted compatibility policy. Those values were still passed as separate parameters and recommendation behavior partly depended on launcher identities, which would make additional launchers and automatic remediation fragile.

### Changes

- Added immutable `LaunchRequest` carrying model, provider, and native launcher arguments.
- Added `LauncherCapabilities` for native-provider affinity, provider-agnostic acceptance, and translated providers.
- Migrated Claude Code, Gemini CLI, Codex CLI, and Aider to one launcher execution contract.
- Changed recommendations to use declared translation and native-provider capabilities instead of a hard-coded Aider ID.
- Routed `modelctl doctor` compatibility checks through the same request object used by execution.
- Added contract, launcher, service, compatibility, and diagnostic regression coverage.
- Preserved all CLI commands, configuration keys, subprocess argument order, and Aider OpenRouter translation.

### Validation and outcome

Dependency audit, Ruff, complete Ubuntu/macOS/Windows tests, package builds, installed-wheel smoke tests, and release dry-run all passed. The refactor merged without changing user-facing commands and now provides the capability and immutable-request boundary used by compatibility remediation.

## 한국어

### 배경

v0.2.0의 첫 세 기능 단위에서 provider-aware 추천, OpenRouter 모델 변환, native 인자 전달, 영속화된 호환성 정책이라는 실제 런타임 요구사항을 확인했습니다. 그러나 해당 값들은 여전히 여러 인자로 분리되어 전달됐고 추천 일부는 launcher ID에 의존하여, launcher 추가나 자동 조치를 확장할 때 구조가 취약해질 수 있었습니다.

### 변경 내용

- Model, provider, native launcher 인자를 함께 전달하는 불변 `LaunchRequest`를 추가했습니다.
- Native provider 관계, provider 범용 수용, 변환 가능한 provider를 표현하는 `LauncherCapabilities`를 추가했습니다.
- Claude Code, Gemini CLI, Codex CLI, Aider를 하나의 launcher 실행 계약으로 전환했습니다.
- 추천이 Aider ID를 하드코딩하지 않고 선언된 변환·native provider capability를 사용하도록 변경했습니다.
- `modelctl doctor`의 호환성 검사도 실제 실행과 같은 request 객체를 사용하도록 통합했습니다.
- Contract, launcher, service, compatibility, diagnostic 회귀 테스트를 추가했습니다.
- CLI 명령, 설정 키, subprocess 인자 순서, Aider OpenRouter 변환은 그대로 유지했습니다.

### 검증 및 결과

Dependency audit, Ruff, Ubuntu·macOS·Windows 전체 테스트, package build, 설치된 wheel smoke test, release dry-run이 모두 통과했습니다. 사용자 명령을 변경하지 않고 병합했으며, 이 실행 계약은 후속 호환성 remediation이 사용하는 capability·불변 request 경계가 되었습니다.

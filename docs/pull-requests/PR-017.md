## English

### Context

The repository could validate a manually proposed tag and build GitHub Release artifacts, but version completion was not represented in a machine-readable form. The release workflow also did not independently run every quality gate, so publication could theoretically proceed while a separate test workflow failed.

### Changes

- Added `release.toml` with coordinated version, readiness status, development channel, and explicit PyPI-disabled policy.
- Added the first `CHANGELOG.md` entry for version `0.1.0`.
- Added bilingual functional, quality, security, and publication completion criteria.
- Extended release validation to cover the manifest, changelog, required documents, and package versions.
- Added regression tests for readiness validation and workflow security properties.
- Made the Release workflow independently run locked dependency audit, Ruff, the complete pytest suite, distribution builds, installed-wheel smoke checks, and checksum generation.
- Added an automatic tag and GitHub Release path for a successful trusted `refac` push marked ready.
- Kept existing tags and GitHub Release assets immutable.
- Kept PyPI publication absent.

### Validation and outcome

CI, Release dry run, Package, and the complete Ubuntu, macOS, and Windows test matrix passed. The release manifest and completion criteria were accepted as ready for `0.1.0`. The connector-based merge did not produce the expected push-triggered tag, which exposed the need for a separately trusted merged-pull-request publication event addressed in the following pull request.

## 한국어

### 배경

저장소는 수동으로 제안된 tag를 검증하고 GitHub Release artifact를 빌드할 수 있었지만, 버전 완료 여부를 기계가 판독할 수 있는 형식으로 표현하지 않았습니다. 또한 Release workflow가 모든 품질 gate를 독립적으로 실행하지 않아 별도 test workflow가 실패해도 게시가 진행될 가능성이 있었습니다.

### 변경 내용

- 통합 version, readiness status, development channel, 명시적 PyPI 비활성 정책을 포함한 `release.toml`을 추가했습니다.
- `0.1.0`의 첫 `CHANGELOG.md` 항목을 추가했습니다.
- 기능, 품질, 보안, 게시 완료 기준을 영문·한국어로 추가했습니다.
- Release validation이 manifest, changelog, 필수 문서, package version을 검증하도록 확장했습니다.
- Readiness 검증과 workflow 보안 속성에 대한 회귀 테스트를 추가했습니다.
- Release workflow가 lockfile dependency audit, Ruff, 전체 pytest, 배포물 빌드, 설치된 wheel smoke test, checksum 생성을 독립적으로 수행하도록 했습니다.
- Ready 상태의 신뢰된 `refac` push가 성공하면 tag와 GitHub Release를 생성하는 경로를 추가했습니다.
- 기존 tag와 GitHub Release asset의 불변성을 유지했습니다.
- PyPI 게시 경로를 추가하지 않았습니다.

### 검증 및 결과

CI, Release dry run, Package, Ubuntu·macOS·Windows 전체 test matrix가 통과했습니다. `0.1.0`의 release manifest와 완료 기준이 ready 상태로 검증됐습니다. 다만 connector 기반 병합에서는 예상한 push-triggered tag가 생성되지 않아, 다음 Pull Request에서 별도로 신뢰된 병합 이벤트 게시 경로를 추가하게 됐습니다.

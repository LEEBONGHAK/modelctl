# PR #28 — Add Google Gemini native model catalog

- Status: Open (draft)
- Base / head: `refac` ← `feat/google-provider`

## English

### Context

PR #27 proved the native-provider workflow with Anthropic and Claude Code. A second native provider is required to confirm that provider registration, official environment aliases, catalog normalization, strict compatibility, recommendation, and remediation are not tied to one vendor.

Google Gemini is the next increment because Gemini CLI is already implemented and declares `google` as its native provider.

### Changes

- Added `GoogleProvider` with provider ID `google`.
- Added a bounded Gemini Models API client for `GET /v1beta/models`.
- Authenticated requests with the official `x-goog-api-key` header.
- Added page size 1,000, page-token pagination, repeated-token detection, and a maximum-page guard.
- Rejected malformed response and pagination metadata explicitly.
- Normalized `models/<id>` resource names to the model ID expected by Gemini CLI.
- Mapped display name, maximum input tokens, generation support, and thinking capability to `UniversalModel`.
- Excluded models that do not advertise `generateContent`, preventing embedding-only models from entering the coding-agent catalog.
- Added `GOOGLE_API_KEY` and `GEMINI_API_KEY` aliases while preserving `MODELCTL_GOOGLE` precedence and the official `GOOGLE_API_KEY`-over-`GEMINI_API_KEY` order.
- Reused the existing Gemini CLI launcher for native recommendation, strict compatibility, and remediation.
- Added regression tests for API headers, pagination, token-loop protection, mapping, filtering, provider discovery, environment resolution, synchronization, and launcher decisions.
- Added bilingual provider documentation and finalized the PR #27 engineering record.

### Security and scope

The client uses a fixed HTTPS endpoint, disables redirects, and applies bounded connect and total timeouts. Pagination is bounded and rejects repeated tokens.

The Google credential managed by modelctl is used for model-catalog synchronization. Gemini CLI continues to manage its own authentication methods. Stored credentials are not copied into launcher subprocess environments automatically.

### Validation and outcome

The pull request remains draft until dependency audit, Ruff, complete Ubuntu/macOS/Windows tests, package builds, installed-wheel smoke tests, and release dry-run all pass.

## 한국어

### 배경

PR #27에서 Anthropic과 Claude Code를 통해 native provider 흐름을 검증했습니다. Provider 등록, 공식 환경변수 alias, catalog 정규화, strict 호환성, 추천, remediation이 특정 vendor에 종속되지 않았는지 확인하려면 두 번째 native provider가 필요합니다.

Gemini CLI가 이미 구현되어 있고 `google`을 native provider로 선언하므로 다음 기능 단위로 Google Gemini를 선택했습니다.

### 변경 내용

- Provider ID가 `google`인 `GoogleProvider`를 추가했습니다.
- `GET /v1beta/models`를 사용하는 제한된 Gemini Models API client를 추가했습니다.
- 공식 `x-goog-api-key` header로 요청을 인증합니다.
- 페이지 크기 1,000개, page-token pagination, 반복 token 탐지, 최대 페이지 제한을 추가했습니다.
- 잘못된 응답과 pagination metadata를 명시적으로 거부합니다.
- `models/<id>` resource 이름을 Gemini CLI가 사용하는 모델 ID로 정규화합니다.
- 표시 이름, 최대 입력 token, 생성 지원, thinking capability를 `UniversalModel`에 매핑합니다.
- `generateContent`를 지원하지 않는 모델은 제외하여 embedding 전용 모델이 coding-agent catalog에 들어오지 않도록 했습니다.
- `MODELCTL_GOOGLE` 우선순위를 유지하면서 `GOOGLE_API_KEY`, `GEMINI_API_KEY` alias를 추가하고 공식 `GOOGLE_API_KEY` 우선순위를 반영했습니다.
- 기존 Gemini CLI launcher를 native 추천, strict 호환성, remediation에 재사용합니다.
- API header, pagination, token 반복 방지, mapper, 필터링, provider discovery, 환경변수 조회, 동기화, launcher 판단을 회귀 테스트로 검증합니다.
- 영문·한국어 provider 문서를 추가하고 PR #27 개발 이력을 완료 상태로 갱신했습니다.

### 보안과 범위

Client는 고정 HTTPS endpoint를 사용하고 redirect를 비활성화하며 connect·전체 timeout을 제한합니다. Pagination은 최대 페이지 수를 제한하고 반복 token을 거부합니다.

modelctl이 관리하는 Google credential은 모델 catalog 동기화에 사용합니다. Gemini CLI는 자체 인증 방식을 계속 사용합니다. 저장된 credential은 launcher subprocess 환경에 자동 복사하지 않습니다.

Dependency audit, Ruff, Ubuntu·macOS·Windows 전체 테스트, package build, 설치 wheel smoke test, release dry-run이 모두 통과할 때까지 draft로 유지합니다.

## English

### Context

v0.2.0 completed provider/model selection, launcher compatibility, remediation, and execution, but users still had to change several global settings independently when moving between recurring workflows. The v0.3.0 roadmap identified named profiles as the next working-first capability before launcher plugin discovery.

### Implemented changes

- Added `ProfileService` with an immutable profile value object.
- Added `modelctl profiles save <name>` to snapshot the current provider, model, launcher, and compatibility policy.
- Added deterministic `list` and `show` commands.
- Added `use` with complete provider/model and launcher validation before one atomic configuration write.
- Added explicit `delete` behavior with unknown-name refusal.
- Normalized profile names to lowercase and constrained their format and length.
- Rejected malformed, partial, or extended stored profile objects.
- Excluded credentials, environment secrets, and launcher-managed authentication data from the profile schema.
- Preserved unrelated configuration keys and all saved profiles during profile application.
- Coordinated workspace, CLI, core, SDK, manifest, and lockfile versions at `0.3.0`.
- Marked the v0.3.0 release manifest as `draft`.
- Updated English and Korean usage, changelog, progress, release criteria, and PR history.

### Validation

- Primary CI passed dependency audit, Ruff, and provider contract tests.
- Complete test suite: 150 passed.
- Ubuntu, macOS, and Windows passed with Python 3.13.
- All wheel and source distributions built successfully.
- Built wheels installed together in an isolated environment.
- Installed package imports, `modelctl version`, and `modelctl --help` passed.
- Release metadata dry-run passes with v0.3.0 in `draft` state.

### Architectural outcome

Profiles apply an explicit validated snapshot to the existing global configuration rather than introducing a hidden runtime overlay. This preserves the meaning of existing `config set`, `use`, `doctor`, and `run` commands and leaves future portability features evidence-driven.

### Deferred work

- Profile import/export, rename, or copy only after concrete usage demonstrates a need.
- Versioned launcher plugin SDK contract and installed entry-point discovery.
- Plugin diagnostics and static type-check enforcement.
- Final v0.3.0 readiness review and publication.

## 한국어

### 배경

v0.2.0에서 provider/model 선택, launcher 호환성, remediation, 실행 흐름을 완성했지만 반복 workflow를 전환할 때 여러 전역 설정을 각각 변경해야 했습니다. v0.3.0 로드맵은 launcher plugin discovery에 앞서 이름 있는 profile을 다음 working-first 기능으로 선정했습니다.

### 구현 변경 사항

- 불변 profile value object를 사용하는 `ProfileService`를 추가했습니다.
- 현재 provider, model, launcher, compatibility policy를 snapshot으로 저장하는 `modelctl profiles save <name>`을 추가했습니다.
- 정렬된 `list`와 상세 `show` 명령을 추가했습니다.
- Provider/model과 launcher 전체 검증 후 설정을 한 번만 원자적으로 저장하는 `use`를 추가했습니다.
- 존재하지 않는 이름을 거부하는 명시적 `delete`를 추가했습니다.
- Profile 이름을 소문자로 정규화하고 형식과 길이를 제한했습니다.
- 손상되거나 일부 필드가 누락되거나 예상하지 않은 필드가 추가된 저장 profile을 거부합니다.
- Credential, 환경변수 secret, launcher가 관리하는 인증정보를 profile schema에서 제외했습니다.
- Profile 적용 시 관련 없는 설정과 모든 저장 profile을 보존합니다.
- Workspace, CLI, core, SDK, manifest, lockfile 버전을 `0.3.0`으로 맞췄습니다.
- v0.3.0 release manifest를 `draft`로 설정했습니다.
- 영문·한국어 사용법, changelog, 진행 현황, release 기준, PR 이력을 갱신했습니다.

### 아키텍처 결과

Profile은 숨겨진 runtime overlay를 추가하지 않고 기존 전역 설정에 명시적으로 검증된 snapshot을 적용합니다. 따라서 기존 `config set`, `use`, `doctor`, `run` 명령의 의미를 유지하며 향후 이식 기능은 실제 필요성이 확인된 뒤 추가할 수 있습니다.

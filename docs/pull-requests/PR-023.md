## English

### Context

Provider-aware launcher recommendations help users select a compatible launcher, but automated and safety-sensitive runs still need a deterministic way to refuse a known provider/launcher mismatch. Native launcher arguments also need to remain pass-through values even when they begin with `--`.

### Changes

- Added opt-in `modelctl run --strict-compatibility`.
- Kept the default compatibility policy non-blocking: normal runs still warn and continue.
- Made strict runs exit before subprocess execution when the active launcher reports a compatibility warning.
- Configured the `run` command to preserve unknown native options such as `--continue`, `--verbose`, and `--sandbox`.
- Added service and CLI regression tests for default warnings, strict blocking, compatible strict runs, and native argument forwarding.
- Updated English and Korean usage, changelog, project progress, and PR history.

### Validation and outcome

Dependency audit, Ruff, packaging, release dry-run, and the complete Python 3.13 test matrix on Ubuntu, macOS, and Windows passed before merge. The command-scoped behavior was merged into `refac` and became the validated foundation for persisted compatibility policy work.

## 한국어

### 배경

Provider-aware launcher 추천은 호환되는 launcher 선택을 돕지만 자동화나 안전이 중요한 실행에서는 알려진 provider/launcher 불일치를 확실하게 거부할 수 있어야 합니다. 또한 `--`로 시작하는 native launcher 인자도 modelctl 오류가 아니라 전달 대상 인자로 유지되어야 합니다.

### 변경 내용

- 선택적으로 사용하는 `modelctl run --strict-compatibility`를 추가했습니다.
- 기본 호환성 정책은 기존처럼 비차단 방식으로 유지하여 일반 실행은 경고 후 계속 진행합니다.
- Strict 실행에서는 active launcher가 호환성 경고를 반환하면 subprocess 실행 전에 종료합니다.
- `run` 명령이 `--continue`, `--verbose`, `--sandbox` 같은 알 수 없는 native 옵션을 launcher에 그대로 전달하도록 구성했습니다.
- 기본 경고, strict 차단, 호환되는 strict 실행, native 인자 전달을 service·CLI 회귀 테스트로 검증했습니다.
- 영문·한국어 사용법, changelog, 프로젝트 진행 문서, PR 이력을 갱신했습니다.

### 검증 및 결과

병합 전에 dependency audit, Ruff, packaging, release dry-run과 Ubuntu·macOS·Windows Python 3.13 전체 테스트가 통과했습니다. Command-scoped 동작은 `refac`에 병합되어 호환성 정책 영속화 작업의 검증된 기반이 되었습니다.

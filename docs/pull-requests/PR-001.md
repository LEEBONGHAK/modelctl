## English

### Context

The repository contained provider, model-selection, configuration, and launcher components, but the intended top-level workflow was not reliably executable. Container wiring, provider identifiers, configuration paths, and interactive selection values were inconsistent.

### Changes

- Exposed `modelctl use` and `modelctl run` as top-level commands.
- Repaired dependency-container wiring for selection and launcher services.
- Added a cross-platform default configuration path and parent-directory creation on save.
- Registered providers by stable provider ID.
- Preserved provider IDs through interactive selection.
- Removed favorite-display markers before persisting model IDs.
- Added regression tests for command registration and selection behavior.

### Validation and outcome

The PR established the first runnable end-to-end command path:

```bash
modelctl use
modelctl run
```

It intentionally deferred broader provider and launcher abstractions until working integrations exposed real requirements.

## 한국어

### 배경

저장소에 provider, 모델 선택, 설정, launcher 구성요소는 존재했지만 사용자가 기대하는 최상위 실행 흐름은 안정적으로 동작하지 않았습니다. 의존성 컨테이너 연결, provider 식별자, 설정 경로, 대화형 선택값 처리에 불일치가 있었습니다.

### 변경 내용

- `modelctl use`와 `modelctl run`을 최상위 명령으로 노출했습니다.
- 선택 및 launcher 서비스의 의존성 컨테이너 연결을 복구했습니다.
- 운영체제 공통 기본 설정 경로와 저장 시 상위 디렉터리 생성을 추가했습니다.
- 안정적인 provider ID를 기준으로 provider를 등록했습니다.
- 대화형 선택 과정에서 provider ID가 유지되도록 수정했습니다.
- 즐겨찾기 표시 문자가 모델 ID에 저장되지 않도록 처리했습니다.
- 명령 등록과 선택 동작에 대한 회귀 테스트를 추가했습니다.

### 검증 및 결과

다음의 최초 종단 간 실행 흐름을 사용할 수 있게 됐습니다.

```bash
modelctl use
modelctl run
```

광범위한 provider·launcher 추상화는 실제 연동 요구사항이 충분히 드러날 때까지 의도적으로 연기했습니다.

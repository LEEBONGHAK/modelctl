## English

### Context

PR #37 defined a public SDK contract but intentionally did not load third-party code. This increment adds the smallest installed-package discovery path while preserving built-in launcher priority and existing recommendation, remediation, compatibility, and execution semantics.

### Implemented changes

- Added the dedicated `modelctl.launchers` Python entry-point group to the public SDK contract.
- Discover only already-installed package entry points from that group.
- Sort candidates deterministically before evaluating them.
- Reject built-in launcher ID collisions before external code is loaded.
- Reject all external candidates when multiple installed entry points claim the same launcher ID.
- Load remaining plugins independently so one broken package cannot block unrelated launchers.
- Accept a plugin instance, zero-argument class, or zero-argument factory returning the public `LauncherPlugin` contract.
- Validate public metadata, capabilities, contract compatibility, and entry-point-name/launcher-ID equality.
- Adapt successful plugins into the existing core `Launcher` runtime.
- Expose distribution source and load status in `modelctl launchers list`.
- Keep failed imports, initialization failures, incompatible contracts, metadata mismatches, and duplicate IDs visible as diagnostic rows.
- Add an installed-package fixture and isolated wheel smoke verification.

### Security boundaries

- No arbitrary filesystem plugin paths.
- No remote registry or code download.
- No automatic package installation or update.
- No provider plugins.
- Built-in IDs cannot be replaced by an installed plugin.
- Installed Python entry points remain executable trusted extension code and are not sandboxed.

### Validation

The PR validates unit-level discovery behavior, CLI diagnostics, cross-platform regression behavior, isolated package installation, and actual installed entry-point discovery before merge.

### Deferred work

- Extend `modelctl doctor` with richer plugin diagnostics.
- Harden recommendation/remediation/strict compatibility regression coverage for external plugins.
- Add the planned static type-check quality milestone.

## 한국어

### 배경

PR #37에서 공개 SDK 계약을 정의했지만 의도적으로 제3자 코드를 로드하지 않았습니다. 이번 increment는 built-in launcher 우선순위와 기존 추천, remediation, 호환성, 실행 의미를 유지하면서 가장 작은 설치 package discovery 경로를 추가합니다.

### 구현 변경 사항

- 공개 SDK 계약에 전용 `modelctl.launchers` Python entry-point group을 추가했습니다.
- 해당 group에 등록된 이미 설치된 package entry point만 탐색합니다.
- 후보를 검증 전에 결정적인 순서로 정렬합니다.
- Built-in launcher ID와 충돌하는 경우 외부 코드를 로드하기 전에 거부합니다.
- 여러 외부 entry point가 동일 launcher ID를 주장하면 해당 후보를 모두 거부합니다.
- 나머지 plugin은 독립적으로 로드하여 하나의 손상된 package가 다른 launcher를 막지 않도록 합니다.
- Plugin instance, 인자 없는 class, 공개 `LauncherPlugin`을 반환하는 인자 없는 factory를 허용합니다.
- 공개 metadata, capabilities, contract 호환성, entry-point 이름과 launcher ID 일치를 검증합니다.
- 성공한 plugin을 기존 core `Launcher` runtime에 adapter로 연결합니다.
- `modelctl launchers list`에 distribution source와 load status를 표시합니다.
- Import 실패, 초기화 실패, 비호환 contract, metadata 불일치, duplicate ID를 진단 행으로 숨기지 않고 표시합니다.
- 설치 package fixture와 격리 wheel smoke 검증을 추가합니다.

### 보안 경계

- 임의 filesystem plugin path를 지원하지 않습니다.
- Remote registry나 코드 다운로드를 지원하지 않습니다.
- Package 자동 설치·업데이트를 지원하지 않습니다.
- Provider plugin은 범위에 포함하지 않습니다.
- 설치 plugin이 built-in ID를 대체할 수 없습니다.
- 설치된 Python entry point는 실행 가능한 신뢰 확장 코드이며 sandbox 대상은 아닙니다.

### 검증

병합 전 unit discovery 동작, CLI 진단, cross-platform 회귀, 격리 package 설치, 실제 설치 entry-point discovery를 검증합니다.

### 후속 작업

- `modelctl doctor`에 더 풍부한 plugin 진단 추가
- 외부 plugin에 대한 recommendation/remediation/strict compatibility 회귀 검증 강화

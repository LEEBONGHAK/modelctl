## English

### Context

PR #37 established the public launcher SDK contract. PR #39 adds the smallest safe runtime discovery path for installed launcher packages. It carries the same implementation lineage validated in PR #38; #38 was closed only because the connected GitHub draft-to-ready mutation failed before merge.

### Implemented changes

- Added the dedicated `modelctl.launchers` Python entry-point group to the public SDK contract.
- Discover only already-installed package entry points from that group.
- Sort candidates deterministically before evaluation.
- Reject built-in launcher ID collisions before external code is loaded.
- Reject all external candidates when multiple installed entry points claim the same launcher ID.
- Load remaining plugins independently so one broken package cannot block unrelated launchers.
- Accept a plugin instance, zero-argument class, or zero-argument factory returning the public `LauncherPlugin` contract.
- Validate metadata, capabilities, contract compatibility, and entry-point-name/launcher-ID equality.
- Adapt successful plugins into the existing core `Launcher` runtime, preserving recommendation and execution semantics.
- Expose distribution source and load status in `modelctl launchers list`.
- Keep import failures, initialization failures, incompatible contracts, metadata mismatches, and duplicate IDs visible as diagnostics.
- Added bilingual `docs/LAUNCHER_PLUGINS.md` documentation and an installed-package fixture.
- Extended package smoke tests to install that fixture into an isolated environment and verify real entry-point discovery.

### Security boundaries

- No arbitrary filesystem plugin paths.
- No remote registry or code download.
- No automatic package installation or update.
- No provider plugins.
- Built-in launcher IDs cannot be replaced by installed plugins.
- Installed Python entry points are executable trusted extension code and are not sandboxed.

### Validation

- Complete test suite: 163 passed.

## 한국어

### 배경

PR #37에서 공개 launcher SDK 계약을 마련했습니다. PR #39는 설치된 launcher package를 위한 가장 작은 안전한 runtime discovery 경로를 추가합니다. 구현 계보는 PR #38에서 검증한 것과 동일하며, #38은 연결된 GitHub Draft → Ready mutation 오류 때문에 병합 전에 종료했을 뿐입니다.

### 구현 변경 사항

- 공개 SDK 계약에 전용 `modelctl.launchers` Python entry-point group을 추가했습니다.
- 해당 group에 등록된 이미 설치된 package entry point만 탐색합니다.
- 후보를 평가 전에 결정적인 순서로 정렬합니다.
- Built-in launcher ID와 충돌하는 외부 entry point는 코드를 로드하기 전에 거부합니다.
- 여러 외부 entry point가 동일 launcher ID를 주장하면 해당 후보를 모두 거부합니다.
- 나머지 plugin은 독립적으로 로드하여 하나의 손상된 package가 다른 launcher를 막지 않도록 합니다.
- Plugin instance, 인자 없는 class, 공개 `LauncherPlugin`을 반환하는 인자 없는 factory를 허용합니다.
- Metadata, capabilities, contract 호환성, entry-point 이름과 launcher ID 일치를 검증합니다.
- 성공한 plugin을 기존 core `Launcher` runtime에 adapter로 연결하여 추천과 실행 의미를 유지합니다.
- `modelctl launchers list`에 distribution source와 load status를 표시합니다.
- Import 실패, 초기화 실패, 비호환 contract, metadata 불일치, duplicate ID를 진단 정보로 숨기지 않습니다.
- 영문·한국어 `docs/LAUNCHER_PLUGINS.md` 문서와 설치 package fixture를 추가했습니다.
- Package smoke test에서 fixture를 격리 환경에 실제 설치하고 entry-point discovery를 검증합니다.

### 보안 경계

- 임의 filesystem plugin path를 지원하지 않습니다.
- Remote registry나 코드 다운로드를 지원하지 않습니다.
- Package 자동 설치·업데이트를 지원하지 않습니다.
- Provider plugin은 범위에 포함하지 않습니다.
- 설치 plugin이 built-in launcher ID를 대체할 수 없습니다.
- 설치된 Python entry point는 실행 가능한 신뢰 확장 코드이며 sandbox 대상은 아닙니다.

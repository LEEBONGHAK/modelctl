# PR #29 — Add OpenAI native catalog and harden provider CI

- Pull request: https://github.com/LEEBONGHAK/modelctl/pull/29
- Status: Open (draft)
- Base / head: `refac` ← `feat/openai-provider-ci-hardening`

## English

### Context

PRs #27 and #28 validated the native-provider contract with Anthropic and Google. OpenAI is the third native provider and completes the current set of provider-to-launcher routes because Codex CLI already declares `openai` as its native provider.

The previous PR also exposed a CI visibility gap: a provider regression failed the OS test matrix and release dry-run while the primary CI workflow remained green because it ran only audit and lint checks.

### Changes

- Added `OpenAIProvider` with provider ID `openai`.
- Added an OpenAI Models API client for `GET /v1/models`.
- Authenticated requests with `Authorization: Bearer <api-key>`.
- Used a fixed HTTPS endpoint, disabled redirects, and bounded connect and total timeouts.
- Rejected malformed model-list responses explicitly.
- Added a conservative coding-candidate filter for GPT, o-series, and Codex model IDs.
- Excluded embedding, image, audio, transcription, TTS, moderation, realtime, search, computer-use, deep-research, Sora, and fine-tuned IDs.
- Mapped only fields confirmed by the Models API response; unavailable context, pricing, and vision metadata are not guessed.
- Added `OPENAI_API_KEY` support while preserving `MODELCTL_OPENAI` precedence.
- Reused the existing Codex CLI launcher for native recommendation, strict compatibility, and remediation.
- Added client, response-validation, mapping, filtering, environment, synchronization, and launcher-decision regression tests.
- Added provider API contract tests to the primary CI workflow.
- Added bilingual OpenAI provider documentation and finalized the PR #28 record with its failure analysis.

### CI hardening

The primary CI job now runs the Anthropic, Google, and OpenAI provider contract suites after dependency audit and Ruff. The complete OS test matrix and release dry-run remain independent gates, but provider HTTP regressions can no longer leave the primary CI result green.

This is intentionally a focused check rather than another duplicate full pytest run.

### Authentication boundary

The OpenAI credential managed by modelctl is used for model-catalog synchronization. Codex CLI continues to manage its own supported authentication methods. Stored credentials are not copied into launcher subprocess environments automatically.

### Validation and outcome

The pull request remains draft until dependency audit, Ruff, provider contract tests, complete Ubuntu/macOS/Windows tests, package builds, installed-wheel smoke tests, and release dry-run all pass.

## 한국어

### 배경

PR #27과 #28에서 Anthropic 및 Google을 통해 native provider 계약을 검증했습니다. OpenAI는 세 번째 native provider이며, Codex CLI가 이미 `openai`를 native provider로 선언하므로 현재 provider-to-launcher 경로를 완성합니다.

이전 PR에서는 provider 회귀가 OS 테스트 matrix와 release dry-run을 실패시켰지만 primary CI가 audit과 lint만 실행해 green 상태로 남는 CI 가시성 문제가 드러났습니다.

### 변경 내용

- Provider ID가 `openai`인 `OpenAIProvider`를 추가했습니다.
- `GET /v1/models`를 사용하는 OpenAI Models API client를 추가했습니다.
- `Authorization: Bearer <api-key>`로 요청을 인증합니다.
- 고정 HTTPS endpoint를 사용하고 redirect를 비활성화하며 connect·전체 timeout을 제한합니다.
- 잘못된 모델 목록 응답을 명시적으로 거부합니다.
- GPT, o-series, Codex 모델 ID를 위한 보수적인 coding candidate 필터를 추가했습니다.
- Embedding, image, audio, transcription, TTS, moderation, realtime, search, computer-use, deep-research, Sora, fine-tuned ID는 제외합니다.
- Models API 응답에서 확인되는 필드만 매핑하며 context, 가격, vision metadata는 추측하지 않습니다.
- `MODELCTL_OPENAI` 우선순위를 유지하면서 `OPENAI_API_KEY`를 지원합니다.
- 기존 Codex CLI launcher를 native 추천, strict 호환성, remediation에 재사용합니다.
- API client, 응답 검증, mapper, 필터링, 환경변수, 동기화, launcher 판단을 회귀 테스트로 검증합니다.
- Primary CI workflow에 provider API contract 테스트를 추가했습니다.
- 영문·한국어 OpenAI provider 문서를 추가하고 PR #28 기록에 실패 분석과 최종 결과를 반영했습니다.

### CI 강화

Primary CI job은 dependency audit와 Ruff 이후 Anthropic, Google, OpenAI provider contract suite를 실행합니다. 전체 OS 테스트 matrix와 release dry-run은 독립 gate로 유지하지만 provider HTTP 회귀 때문에 primary CI만 green으로 남는 상태는 방지합니다.

전체 pytest를 중복 실행하지 않고 실패 원인과 직접 관련된 테스트만 추가했습니다.

### 인증 경계

modelctl이 관리하는 OpenAI credential은 모델 catalog 동기화에 사용합니다. Codex CLI는 자체 지원 인증 방식을 계속 사용합니다. 저장된 credential은 launcher subprocess 환경에 자동 복사하지 않습니다.

### 검증 및 결과

Dependency audit, Ruff, provider contract 테스트, Ubuntu·macOS·Windows 전체 테스트, package build, 설치 wheel smoke test, release dry-run이 모두 통과할 때까지 draft로 유지합니다.

## English

### Context

As the configuration and launcher workflow expanded, users needed one command to explain why a local setup could not run. The first diagnostic version prioritized actionable status over automatic repair.

### Changes

- Added a core diagnostic service.
- Added top-level `modelctl doctor` with Rich table output.
- Checked configuration-file availability.
- Checked selected provider, credential, model, and launcher state.
- Checked launcher installation and SQLite connectivity.
- Returned exit code `1` for required configuration or runtime failures.
- Treated missing credentials and launcher executables as actionable warnings.
- Added healthy and incomplete-configuration tests.

### Validation and outcome

Users gained a single preflight command:

```bash
modelctl doctor
```

The service later became the shared presentation point for provider/model/launcher compatibility feedback.

## 한국어

### 배경

설정과 launcher 흐름이 확장되면서 로컬 환경이 실행되지 않는 이유를 한 번에 설명해 주는 명령이 필요했습니다. 최초 진단 기능은 자동 수정 대신 이해하기 쉬운 상태와 조치 방법 제공에 집중했습니다.

### 변경 내용

- Core diagnostic service를 추가했습니다.
- Rich Table을 출력하는 최상위 `modelctl doctor` 명령을 추가했습니다.
- 설정 파일 존재 여부를 검사했습니다.
- 선택된 provider, credential, model, launcher 상태를 검사했습니다.
- launcher 설치 여부와 SQLite 연결을 검사했습니다.
- 필수 설정 또는 런타임 오류에는 종료 코드 `1`을 반환했습니다.
- credential이나 launcher 실행 파일 누락은 조치 가능한 경고로 처리했습니다.
- 정상 환경과 미완성 환경 테스트를 추가했습니다.

### 검증 및 결과

사용자는 다음 단일 명령으로 실행 전 상태를 점검할 수 있게 됐습니다.

```bash
modelctl doctor
```

이후 provider·model·launcher 호환성 피드백도 같은 진단 서비스에 통합됐습니다.

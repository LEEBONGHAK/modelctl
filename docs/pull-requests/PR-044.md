# PR #44 — Fix first-release tag detection

- Pull request: https://github.com/LEEBONGHAK/modelctl/pull/44
- Base branch: `main`
- Head branch: `fix/v0.3.0-release-tag-detection`
- Created: 2026-09-01
- Status: validation in progress

## English

### Context

PR #43 successfully promoted the fully validated v0.3.0 readiness lineage to `main` at merge commit `42fb7d27eeac009943665cac1a5042455a4c9c6e`. The post-merge Release workflow then passed release metadata validation, clean dependency audit, Ruff, strict basedpyright, the complete test suite, all builds, installed-wheel checks, and checksum generation.

The final publisher step nevertheless produced no tag or GitHub Release. Its tag lookup used a command substitution ending in `|| true`. When the first-time `v0.3.0` lookup returned 404, `gh api` wrote the JSON error body to stdout; `|| true` erased the failure status, so the JSON body was assigned to `existing_tag_sha`. The publisher then treated that body as a conflicting existing SHA and exited successfully without publishing.

### Fix

- Preserve the failed `gh api` status inside an `if` condition rather than converting it to success.
- Explicitly reset `existing_tag_sha` to empty when the tag lookup fails.
- Preserve existing protection against overwriting a real tag that points elsewhere.
- Add a workflow regression test that requires the missing-tag branch and rejects the previous `|| true` lookup pattern.
- Record the fix in the v0.3.0 changelog.

### Release safety

This PR changes release automation only. modelctl runtime behavior and v0.3.0 package contents are unchanged except for release documentation/tests. `release.toml` remains `0.3.0` / `ready`, PyPI publication remains disabled, and the complete ready-release validation must pass again before merge.

## 한국어

### 배경

PR #43은 완전히 검증된 v0.3.0 readiness 계보를 `main` merge commit `42fb7d27eeac009943665cac1a5042455a4c9c6e`로 성공적으로 승격했습니다. 이후 post-merge Release workflow에서도 release metadata 검증, clean dependency audit, Ruff, strict basedpyright, 전체 테스트, 모든 build, installed-wheel 검증, checksum 생성이 통과했습니다.

하지만 최종 publisher 단계에서 tag와 GitHub Release가 생성되지 않았습니다. 기존 tag 조회 command substitution이 `|| true`로 끝났기 때문입니다. 최초 `v0.3.0` 조회의 404에서 `gh api`가 JSON 오류 본문을 stdout에 출력했고, `|| true`가 실패 status를 지우면서 이 JSON이 `existing_tag_sha`에 저장되었습니다. Publisher는 이를 충돌하는 기존 SHA로 오인하고 성공 상태로 종료해 게시를 건너뛰었습니다.

### 수정

- 실패한 `gh api` status를 `if` 조건에서 그대로 사용하고 성공으로 강제 변환하지 않습니다.
- Tag 조회 실패 시 `existing_tag_sha`를 명시적으로 빈 값으로 초기화합니다.
- 실제 기존 tag가 다른 commit을 가리킬 때 덮어쓰지 않는 보호는 유지합니다.
- Missing-tag 분기를 강제하고 기존 `|| true` 패턴 재도입을 막는 workflow regression test를 추가합니다.
- v0.3.0 changelog에 수정 사항을 기록합니다.

### 릴리스 안전성

이번 PR은 release automation만 수정합니다. modelctl runtime 동작은 변경하지 않으며 release 문서/테스트 외 v0.3.0 package 기능도 그대로입니다. `release.toml`은 `0.3.0` / `ready`를 유지하고 PyPI 게시는 계속 비활성화하며, 병합 전에 complete ready-release validation을 다시 통과해야 합니다.
